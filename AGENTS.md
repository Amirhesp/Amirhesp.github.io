## What this is

A single-page personal/professional site for Amirhossein Esmaeilipour, built with
Astro and Tailwind v4, deployed as static files to GitHub Pages. There is no
backend, no database, and no server-rendered route — `astro build` emits plain
HTML and the host only serves files.

## Commands

Node **22** is required (`.nvmrc`); the system Node is 18 and is too old for
Astro. Every session needs nvm loaded first:

```bash
export NVM_DIR="$HOME/.nvm" && . "$NVM_DIR/nvm.sh" && nvm use
```

| Command | Purpose |
| --- | --- |
| `npm run dev` | Dev server with HMR on `localhost:4321` |
| `npm run build` | Static build into `dist/` |
| `npm run preview` | Serve the built `dist/` — use this, not `dev`, to check what actually deploys |

There is no test suite and no linter. Verification is: build succeeds, then
inspect the rendered page (see below).

## Architecture

**All content lives in `src/data/profile.ts`.** This is the load-bearing
convention of the repo. Components read from the exported `profile` object and
contain no copy of their own. Adding a job, project, or skill is an edit to that
file only — if a content change requires touching a `.astro` file, the component
is under-parameterised and should be fixed rather than worked around.

`src/pages/index.astro` is the whole site: it imports `Base.astro` and stacks the
section components in order. Each section component wraps its content in
`Section.astro`, which owns the shared max-width, vertical rhythm, and heading
style — spacing is defined there once, not per section.

`Base.astro` holds the `<head>`: meta tags, Open Graph tags, and the JSON-LD
`Person` schema, all derived from `profile`. The OG and canonical URLs are built
from `Astro.site`.

Tailwind v4 is configured **in CSS**, not a config file. Design tokens (the
`accent-*` teal scale, font stack) are in the `@theme` block of
`src/styles/global.css`. There is no `tailwind.config.js`, and adding one would
be ignored.

Dark mode is `prefers-color-scheme` only, via Tailwind `dark:` variants. There is
no theme toggle and no theme JavaScript — the page ships zero JS, and it should
stay that way.

## Deployment

Push to `main` → `.github/workflows/deploy.yml` builds and publishes to GitHub
Pages. Repo Settings → Pages → Source must be **GitHub Actions** (not "deploy
from a branch").

The repo is named `Amirhesp.github.io`, making it a GitHub *user site* served at
the domain root. This is why `astro.config.mjs` has **no `base` path**. Renaming
the repo would turn it into a project site served under `/repo-name/` and break
every absolute asset path.

`site` in `astro.config.mjs` must match the deployed origin — it feeds the
sitemap, canonical URL, and OG tags. It is the one line to change when a custom
domain is attached.

## Checking a change

`npm run build && npm run preview`, then screenshot with headless Chrome. Note
that `--force-dark-mode` does *not* emulate `prefers-color-scheme`; use
`--blink-settings=preferredColorScheme=0` for dark and `=2` for light.

```bash
google-chrome --headless --disable-gpu --no-sandbox --hide-scrollbars \
  --window-size=1280,4400 --screenshot=out.png http://localhost:4321/
```

Content must be present in `dist/index.html` itself — `grep` for a phrase to
confirm static rendering rather than client-side hydration.

`public/og.png` is the social preview card, generated by a script rather than
hand-drawn; regenerate it if the name, title, or tagline in `profile.ts` change.
